# A25-RC2 staging drill kit — SEALED AUTHOR EDITION

Dry-run default; this edition cannot call Render or contact real staging/Production, even with --execute. Every executing mode requires an unexpired CEO_STAGING_ONLY reference in the inventory and literal loopback targets. No DNS names, credentials, redirects, Render mutation adapter or database connection is accepted. Approval metadata is a guard against accidental use, not an authentication mechanism. Network isolation and operator authority are separate controls.

Copy inventory.example.json to a local synthetic inventory, complete P1–P13 and peers, then run `python operations/a25_rc2/drill.py steps inventory.json`. The example is deliberately incomplete and must fail validation. For a complete inventory, `... probes inventory.json` and `... trading inventory.json` only print dry-run plans. `--execute` enables loopback synthetic collection only. Mutation intent is an operator worksheet; it never mutates resources. Real staging execution requires a separately scoped, reviewed platform adapter after CEO authorisation. This deliberate limitation remains an acceptance blocker; do not describe this kit as an executable Render deployment tool.

Probe records include timestamps, target/vantage, path, method, status and error; analytics response bodies are never stored. Real WebSocket handshake101 or any analytics2xx stops collection. Repeat across the whole window with <=10s coverage; split targets into independently authorised workers if the bounded batch exceeds10s. Unknown/timeout responses do not establish a working denial: record availability and positive-control evidence separately. A staging sender must report requests, acknowledgements, fresh-connection persisted rows, duplicates and missed-window counts. This kit leaves persisted marked unverified until operator DB evidence is joined. collect-sql hashes an operator-exported synthetic statement log and counts SELECT lines; it is not a SQL audit classifier or proof of zero analytics SELECTs. Correlate engine hitmon, timestamps and actual DB logs under independent review.

Deliberate failing build: use a disposable copy with requirements digest altered, expecting preflight failure. Deliberate failing start: append `raise ImportError('SYNTHETIC_START_FAULT')` only to a disposable engine copy. Deliberate failing health: configure a staging-only invalid health path in the future authorised operator worksheet. None of these mutations touches a reviewed source tree or live service.
